# Backlog

**Purpose**: Tasks that sit outside every feature's phase order — defects and refinements found along the way that no story depends on, and work deferred because it waits on something outside the project, such as a device. Kept here, in one file, rather than at the end of whichever feature's `tasks.md` raised them, so they are not lost once that feature is done. Each is picked up when it is chosen, not when a phase comes round.

**Conventions**: Ids are the same series as every feature's tasks (`.claude/rules/workflow.md`) — a task raised here takes the next free id, after reading every `specs/*/tasks.md` and this file for the highest. Tasks are grouped by the feature that raised them, and a story label, FR, SC, or research id inside a task refers to that feature's documents. Closing one marks it `[X]` here in the same commit, with the id in the commit scope as for any task.

## From 001 — Emergency fund tracker

Documents: [`specs/001-emergency-fund-tracker/`](001-emergency-fund-tracker/). Moved from that feature's Improvements section on 2026-11-08.

- [ ] T159 [US2] Recompute what depends on today when the date changes under a running app — the balance is computed from `clock.today()` only when a screen renders (`useBalance`'s `select`), and the future-dated check is keyed by the date it was asked on, so a date that changes while the app is open leaves both as they were drawn. Seen on the Android emulator during T085: an entry recorded with the clock four days ahead, the clock set back, and Home went on showing R$ 3.000,00 and "1 de 6 meses" with that entry counted, where a cold start showed R$ 500,00 and "0 de 6 meses". The clock correction is exactly how FR-033's entries arise, and midnight is the same change in the other direction. Probably a re-render, and a refetch of the date-keyed queries, when the app returns to the foreground or the day turns over; what triggers it is for the task to measure. Raised during T085. Numbered out of sequence for the reason T156 is (001's `tasks.md`)
- [ ] T160 [US5] Ask before an edit takes a withdrawal above the balance (FR-017) — `recordEntry` refuses an unconfirmed over-balance withdrawal with an `over-balance` error, but `reviseEntry` checks only `validateEntry`, so correcting a withdrawal of R$ 100,00 to R$ 5.000,00 on the edit screen lands without the question. The balance to measure against is the ledger as of today with the entry's stored amount taken out, not counted twice. The edit screen then needs the confirmation the withdraw screen has (`WithdrawConfirm`), re-sending the patch with the confirmation. Tests first: a unit case in `revise-entry.test.ts` at, just over, and confirmed over the balance, and a component case on the edit screen. Raised during T117–T125. Numbered out of sequence for the reason T156 is (001's `tasks.md`)
- [ ] T145 Build the erase-all-data flow with `ConfirmSheet` in `src/features/data-transfer/erase.tsx` — the erase itself exists since T087 (`StoreRepository.eraseAll`); what remains is the flow and its confirmation. - [ ] T193 [US2] Find and fix the intermittent `act(...)` warning in `tests/component/dev-seed.test.tsx` — in some full `npm run verify` runs the suite logs "An update to Seeding inside a test was not wrapped in act(...)", raised from TanStack Query's `notifyManager` timeout, so a mutation's state change on the seed screen (`app/dev/seed.tsx`, `useSeed`) lands after the test has stopped watching. Measured on 2026-11-08 across six runs of the component project with coverage: 0, 2, and 3 occurrences with the drawer's test setup registered, 2, 0, and 0 without it, so it predates feature 002 and comes and goes with timing. Which test leaves the update behind is for the task to find, by running the file alone and in the full project; the fix is to wait for the consequence the update causes, not for something already on screen (AP-013). - [ ] T196 Keep a one-word screen title whole at the largest text size (001 FR-050) — at iOS's largest accessibility size (`accessibility-extra-extra-extra-large`), the Statistics title breaks mid-word, "Estatí" over "sticas". Other one-word titles ("Histórico", "Previsão") were not looked at and may do the same, and Android's largest font scale was not checked on a section title. What to do is for the task to decide — a smaller ceiling on the title's scale (`maxFontSizeMultiplier` on the heading variant only), letting the title shrink to fit, or a hyphenation hint — and FR-050's "full use at the largest text size" is the measure. Tests at maximum text scale are T147's (001, Phase 10); this one is visible only on a device. Raised during T190 (feature 002)

- [ ] T195 Decide whether Goal and Reminders belong under a heading of their own in the menu, apart from "Navegação" — raised by the user on 2026-11-08, after Phase 4. Every item sits today under the one "Navegação" heading, but the six do not behave alike: Home, History, Statistics, and Forecast are places the menu switches between, while Goal and Reminders are forms that open over the current screen and go back to it (spec, Clarifications; `presentation: 'over'` in `src/features/navigation/destinations.ts`). Changing it touches FR-001 (one list, in that order), the menu's contract (`contracts/navigation-ui.md`, `menuLabel` is the one header a screen reader lands on when focus enters, per R-001 and T194), `strings.navigation`, the menu's component tests, and `e2e/navigation-menu.yaml`. Waits for T194, agreed with the user: a second heading changes where a screen reader lands and moves in the menu, so it is decided once that has been measured.
